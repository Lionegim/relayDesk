# Live inbox updates

The browser opens `/api/events` after loading its owner session and inbox. Committed repository writes affecting messages, accounts, contacts, folders or sync progress trigger coalesced invalidations. The stream carries only an empty object, never message bodies, account identities, keys or send approvals. The browser fetches the current filtered list and selected conversation through the existing private APIs.

WhatsApp notifications now update the list and open chat without a page refresh. Typed drafts, selected conversations and reading position are retained. Live refresh waits while an exact-preview confirmation or connection wizard is open, then catches up. A detail invalidation arriving during an older request supersedes that response and forces another read. Failed reads retry with bounded backoff, including when no further message arrives.

Gmail and Outlook still check their providers automatically every 60 seconds in the hosted configuration. Once imported, their changes reach the browser immediately through the same live channel. This feature does not add Google Pub/Sub or Microsoft Graph webhooks. It also does not add operating-system push notifications while the app is closed; mobile/background tabs may be suspended by the browser.

The stream uses the existing owner cookie and host checks, rejects cross-origin/Fetch Metadata requests, revalidates the original session before each frame and every 15-second heartbeat, and does not extend idle session lifetime itself. There are at most six streams per session and 64 overall; slow readers are disconnected rather than accumulating unbounded buffers. Revocation or expiry closes the stream. Events are not retained or replayed: every successful connection fetches a fresh snapshot, covering missed changes and server restarts. EventSource retries connections after approximately two seconds, with the existing 30-second polling fallback while disconnected. The runtime closes streams before draining HTTP during shutdown.

No schema migration, provider credentials, account permissions, mail-sending code or approval tickets are changed. Exact-preview approval stays bound to the owner session and exact content and remains single use. Live updates only read and render; they cannot approve or send a message. Service-worker cache version 7 includes the generic live client module, never API/event responses.

Caddy already recognizes `text/event-stream` and flushes streaming responses without waiting for its normal response buffer: [official reverse_proxy streaming documentation](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#streaming). The application also sends `Cache-Control: no-store` and `X-Accel-Buffering: no`.

Validation uses fictional data: fake WhatsApp socket arrivals delivered to two authenticated screens, anonymous/cross-origin rejection, session revocation and expiry, bounded clients/backpressure, graceful shutdown, browser reconnect/coalescing, delayed and failed detail reads, and draft preservation without sending. A Chrome fixture demonstrates an incoming WhatsApp message appearing in the already-open conversation while preserving a typed draft; the fake provider records zero sends.
